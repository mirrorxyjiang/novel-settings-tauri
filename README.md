# Story-Box · 故事魔盒

**Story-Box（故事魔盒）** —— 给小说作者自己用的创作桌面应用：以「书籍」为单位，管理人物、地图、大纲、时间线与正文；每个模块下可以自由新建页面，页面可以是**绘图区**（画布、图标、连线、背景图层）或**文字区**（富文本笔记），页面还能无限层级地嵌套子页面。

基于 [Tauri 2](https://tauri.app) + React 构建，数据以 JSON 文件存在本地磁盘，存储目录可指向任意云盘同步文件夹（OneDrive / iCloud云盘 / 坚果云……），不依赖账号或服务器。

> 这是个人向的创作工具，没有多人协作、没有后端服务，你的数据只存在你自己的电脑（和你自己选的云盘）里。

---

## 界面结构

```
书籍
├─ 地图（可加绘图页 / 文字页 / 时间线，支持子页面）
├─ 人物
├─ 大纲
├─ 自定义模块（可自己加，位于正文模块上方）
└─ 正文（每本可建多个，自带「变量」页 + 文字页，一键导出 txt）
```

## 功能一览

**书籍 / 模块 / 页面结构**
- 每本书默认包含「地图」「人物」「大纲」「正文」四个模块，可随时新建自定义模块（排在正文模块之前）和额外的正文模块
- 书籍、模块、页面都支持重命名：书籍点 ✎，页面在侧边栏双击名字或直接在页面顶部标题框里改
- 页面支持**任意层级的子页面**——一个页面下面还能再挂子页面，适合把复杂设定拆成主页 + 细节页
- 书籍、模块、页面删除时都会弹出确认框再执行

**正文模块**
- 「变量」页：把正文里反复出现的人名地名集中定义，分 **角色（≤4 字）/ 地点 / 势力 / 物品（≤8 字）** 四类横向排布，每类带序号、最多 12 个，可用 ▲▼ 调整顺序
- 文字页上边栏是**变量板**：按四类各一行展示，点击变量即可插入到正文光标处，写作时不用反复手打人名
- **一键导出**：正文模块标题行的 ⇩ 按钮把模块内所有文字页面（含各级子页面）导出为 txt，每个页面一个文件

**文字区**
- 基础富文本：加粗、斜体、下划线、有序/无序列表、标题
- 输入停顿 1 秒自动保存，失焦立即保存；页面顶部另有「💾 立即保存」按钮

**时间线**
- 「年 → 月 → 日 → 时辰」四级可折叠/展开的表头，横向滚动时行首的角色列与行名列固定
- 格子可填内容、设置背景色（危机/交友/情缘……可自定义图例）、挂图标批注
- 每个角色模块可自定义行（默认 地点 / 人物 / 事件）

**绘图区**
- 矩形 / 圆形 / 直线 / 箭头 / 文本框，拖拽创建；边框颜色·粗细·线型（实线虚线点线）、填充颜色·透明度均可自定义
- 16 个内置图标可直接点选放置，也支持导入自己的图片作为图标
- **背景图层**（地图模块常用）：导入底图后可拖动/缩放，标注完成后可锁定防误触
- 画布支持**缩放**（工具栏 +/− 或 Ctrl/Cmd + 滚轮）与**抓手平移**（抓手工具或按住空格键临时切换）
- 图形/图标可加备注；连线可拖动端点、可加文字标签；文本框支持自定义颜色与加粗

**存储与迁移**
- 每本书是独立 JSON 文件，导入的图片单独存成文件（不再内嵌 base64，避免书籍文件越滚越大）
- 书库首页可随时查看/更改存储目录——指向云盘同步文件夹，换电脑后重新指向同一文件夹即可迁移全部数据
- 删除书籍是软删除，文件移到 `books/.trash/`，误删可手动找回

## 技术栈

- [Tauri 2](https://tauri.app)（Rust 外壳 + 系统 WebView）
- React 18 + Vite
- 纯 SVG 手写画布引擎（不依赖 Konva/Fabric 等第三方绘图库）
- 本地文件系统存储，无数据库、无后端

> 交互提示都走**应用内自绘弹窗**（`src/App.jsx` 里的 `DialogProvider`）：Tauri v2 的 WebView 没有实现 JS 原生 `confirm` / `prompt` / `alert`，直接用它们在打包后的桌面端会静默失效。

## 快速开始

### 前置环境

1. **Node.js**（建议 18+）与 npm
2. **Rust 工具链**：<https://www.rust-lang.org/tools/install>，装完新开终端执行 `rustc --version` 确认
3. **Tauri 所需的系统依赖**（每台开发机配置一次）：
   - Windows：Microsoft C++ Build Tools（Rust 安装向导会自动引导）、WebView2（Win10/11 通常自带）
   - macOS：`xcode-select --install`
   - Linux：`webkit2gtk`、`libssl-dev` 等，包名因发行版而异，参见 [Tauri 官方文档](https://tauri.app/start/prerequisites/)

### 安装与开发

```bash
git clone https://github.com/mirrorxyjiang/story-box.git
cd story-box
npm install        # 想严格按锁定版本装，可用 npm ci
npm run tauri dev
```

首次运行会编译 Rust 部分，耗时可能几分钟，之后自动弹出桌面窗口。只想改前端界面的话，`npm run dev` 单独跑 Vite 也行（存储相关的 invoke 调用会不可用）。

### 打包发布

```bash
npm run tauri build
```

打包前建议：
1. 图标：`src-tauri/icons/` 下的图标由 `npx tauri icon <源图>` 生成（源图放在 `src-tauri/icons-source/`）
2. 把 `src-tauri/tauri.conf.json` 里的 `identifier` 改成你自己的唯一标识（反转域名风格，当前为 `com.storybox.app`）

### 换一台电脑：装软件 + 搬数据

`npm run tauri build` 结束后，安装包在 **`src-tauri/target/release/bundle/`** 里：

| 平台 | 产物 |
|---|---|
| Windows | `msi/*.msi`（公司/组策略部署友好）和 `nsis/*.exe`（双击安装，推荐） |
| macOS | `dmg/*.dmg`、`macos/*.app` |
| Linux | `deb/*.deb`、`appimage/*.AppImage` |

**第一步：在新电脑上安装**
把 `.exe`（或 `.msi`）拷过去双击安装即可。因为没有代码签名证书，Windows SmartScreen 会拦一下：点**更多信息 → 仍要运行**放行；macOS 如果提示"无法打开"，在访达里右键应用选**打开**。应用不会自动更新，出新版本就再跑一次安装包覆盖安装。

**第二步：把书籍数据搬过去（两种方式，任选）**

*方式 A：拷文件夹（最简单，推荐先做这个）*

1. 老电脑上打开应用 → 书库首页看「当前存储位置」这一行的路径（默认是在系统应用数据目录里的 `StoryBoxData`）
2. 把这个**整个 `StoryBoxData` 文件夹**（里面有 `books/` 和每个书的 `xxx-assets/` 图片文件夹）拷进 U 盘 / 网盘
3. 新电脑装好应用后先把这一份拷到本地任意位置（例如 `D:\StoryBoxData`），打开应用 → 点「更改存储位置」→ 选中它 → 立刻就能看到全部书籍
4. `books/.trash/` 是回收站，不用拷

*方式 B：指向云盘同步文件夹（长期多台电脑用，推荐）*

1. 把上面的 `StoryBoxData` 文件夹放进 OneDrive / iCloud云盘 / 坚果云的同步目录，例如 `OneDrive\StoryBoxData`
2. 两台电脑上都打开应用 → 「更改存储位置」→ 都指向**同一个云盘目录**
3. 之后哪台电脑改了内容，另一台等云盘同步完成后**重启应用**就能看到（应用启动时才读盘，不会热重载）

两种方式的注意事项：
- **图片是跟着书走的**：每本书的图片单独存在 `books/<书籍id>-assets/` 里，书籍 JSON 只存相对路径。只拷 `*.json` 不拷 `-assets` 文件夹，书能打开但插图会变空白。
- **单本书就是一个 JSON 文件**，想只搬某一本，单独拷 `books/<id>.json` + 对应的 `<id>-assets/` 也行。
- **不要两台电脑同时编辑同一本书**，云盘会产生冲突副本；需要时手动挑一份改名覆盖。
- `config.json`（记录了你选的存储目录）在系统级应用配置目录里，不在数据文件夹内，所以换电脑后一定要手动设一次「更改存储位置」。

## 数据存储结构

```
<数据存储目录>/
└─ books/
    ├─ 8f3ka2mZ.json            一本书 = 一个 JSON 文件，文件名即书籍 id
    ├─ 8f3ka2mZ-assets/         这本书导入的图片（图标 / 背景图）单独存在这里
    │   └─ 1731000000123.png
    ├─ pQ92xLrT.json
    └─ .trash/                   软删除的书籍会移动到这里，而不是直接抹除
```

`config.json`（记录当前生效的存储目录路径）单独存放在系统级应用配置目录，不在上面这个数据文件夹里。

**跨设备迁移**：在新电脑安装本应用 → 书库首页点击「更改存储位置」→ 选择云盘同步文件夹里的数据目录，应用会立即从该目录重新读取书籍列表。不要在两台电脑上同时编辑同一本书，云盘同步可能产生冲突文件。

## 项目结构

```
story-box/
├─ public/                   静态资源（favicon 等），vite 原样拷到构建产物
├─ index.html                前端入口 HTML
├─ package.json
├─ vite.config.js
├─ src/                      前端源码
│   ├─ main.jsx              React 挂载入口（DialogProvider 包在最外层）
│   ├─ App.jsx               核心组件：书籍/侧边栏/绘图区/文字区/时间线/变量页 + 应用内弹窗
│   ├─ ErrorBoundary.jsx     全局错误边界，渲染异常时给可恢复提示页而不是白屏
│   └─ store.js              前端与 Rust 后端的桥接层（封装 invoke 调用）
└─ src-tauri/                Rust 后端
    ├─ Cargo.toml
    ├─ build.rs
    ├─ tauri.conf.json       应用窗口、打包配置
    ├─ capabilities/
    │   └─ default.json      Tauri v2 权限声明
    ├─ icons/                应用图标
    └─ src/
        ├─ main.rs           程序入口
        └─ lib.rs            核心命令：本地文件存储、图片素材、目录选择、配置管理、txt 导出
```
